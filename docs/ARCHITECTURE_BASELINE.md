# MIRROW 公开模块架构边界

## 部署与权威

本仓库是供每位部署者接入自己宿主的本地单用户模块，含漫想配套前端，但不包含完整聊天应用、私人记忆库或设备控制服务。人格、会话消息、当前用户状态和真实设备连接由宿主提供；缺失事实不伪造为已知或成功。

`mirrow_core` 提供配置、时间、人格称呼、宿主状态和模型请求基础件。模型配置来自环境变量；仓库不提供密钥、登录态、网络拓扑或设备标识。

## 上下文

`context_builder` 按 recipe 组织身份、历史与当前事实，`memory_provider.py` 定义可注入的记忆检索边界。原料说明来源、时效与可靠度；模型输出合同与执行边界不混入事实原料。

关系时间线只读取宿主提供的可选事实，未配置时为空。群组动态只有宿主明确传入房间时才读取，成员显示名可配置；发行包不预置相识日期、个人经历或私人群组成员。

`WANDER_V2` 用于计划；`WANDER_ACTIVITY` 用于节点复核、自省与结算；`WANDER_PUSH` 用于活动分享。近期内部漫想从运行时数据库投影，不替代宿主会话历史，且只加入规划配方，不加入当前活动证据。分享调用同时过滤历史中的漫想消息，避免主动输出自我循环。

许愿板页面与自省读取同一存储提供的愿望/评论投影；自省调用边界保留这份完整快照，不再按固定字符数截断愿望或评论。敏感信息清洗仍保留，不通过删除后半段事实来省略材料。

## 漫想配套前端

`wander_frontend` 是独立 React 界面：日志读取 `runtime_store` 已有投影，区分执行状态、分享状态与调度空档；许愿板只在服务端确认后刷新状态与评论，不自行推导愿望已实现。会客与淘宝只有范围说明，不提供专属页面或控制按钮。

`public_api.create_wander_ui_router` 由宿主显式注入已初始化的 runtime/wish stores；前端经同源 `/api/wander` 读取日志及维护许愿板。新许愿板以通用 `user` 存储用户角色；旧角色约束需要宿主提供映射并显式迁移，HTTP 层不自动迁移数据库，也不回传内部来源键和审计载荷。`examples/wander_ui.py` 提供本机启动及静态文件托管示例，默认读取公开模块的 `events` 目录，但不会启动模型、漫想调度或设备服务。完整聊天消息与设备控制仍归宿主负责。

## 漫想主数据流

宿主状态 → `runtime_runner` → 计划 → 活动 → 节点执行与复核 → 结算/自省 → 可选分享。

`runtime_store` 的 SQLite 是漫想运行态权威，保存 run/activity/node/decision/delivery 身份链；`runtime_controller` 决定状态迁移，adapter 执行有界外部工作。重启后的未确认副作用不盲目重放。用户回复触发中断结算，不把恢复时间戳误判为新回复。

`event_catalog` 定义事件目标语义；计划与复核共用有效白名单。目录中的类型不代表宿主已经配置该能力。会客与逛淘宝各为 `single / 1`：一次真实外部活动作为一个节点，其内部流程由外部处理器负责。两者只保留接口，原始集成移植自 AionsHome，不提供实现。

`host_hooks` 注册可选活动、历史仓库、音乐及工作租约。未注册的会客、淘宝、朋友圈、群组活动和书签事件不进入有效白名单。群组活动只保留宿主接口，公开版不提供成员、房间、传输或续话链路；宿主必须返回明确完成证据。听歌需要真实音乐服务与播放确认，不把选歌或分析当成已播放。

小红书提供公共页面与 Android 只读组件、节点适配及人工评论交接组件。设备由部署者配置，跨进程租约只管理本机读取互斥。没有设备、登录或可靠内容时节点跳过或失败，不执行点赞、收藏、关注、评论、发布或支付。

## 分享与宿主消息

分享不能拥有另一份对话真相。宿主回调负责把内容写入自己的权威历史并完成自己的交付流程，明确返回 `True` 后才记录 `sent`；未确认不是成功。`ConfirmedDeliveryGate` 可用于同进程串行和成功回执去重，跨重启去重由宿主以稳定 delivery 身份持久化实现。

勿扰在生成和交付边界检查，被抑制的分享保留 `suppressed`，不在勿扰解除后自动补发陈旧内容。外部处理器返回的通知凭据只能指向它实际完成的交付。

## 其他公开模块

`silicon_perception` 将带时间与来源的感知快照交给宿主；`behavior_scheduler` 将模型决策交给实际注册的工具。原始工具结果、私有服务、移动中继与前端部署不因模块存在而自动获得。自省可产生愿望或候选，不直接覆盖长期人格；外部情绪服务只通过显式注入接收真实结算结果。
