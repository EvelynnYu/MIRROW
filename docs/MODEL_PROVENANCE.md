# 模型来源与手动主聊天切换

公开本地宿主保存新回复的 `generation_model` 附属字段。原始正文不拼接型号，未知旧来源保持为空，不按切换时间或语气补猜。该字段与回复同事务写入，写入后不可修改。

## 上下文

- 历史 assistant 在传输视图中附带短头部 `【生成模型：型号】`，说话人仍是同一个 Agent。
- Provider 使用本次实际请求的模型 ID，规范化为名称与版本后，在动态尾部追加 user 运行信息。稳定首 system 不随模型选择改变。
- 主聊天固定合同说明所有历史仍属于同一 Agent，型号只代表生成来源，不据此猜测性格与情绪原因；首次升级包含这段固定合同的变化。
- 型号标记不包含服务商、站点、倍率或价格。API 请求型号只能证明调用时请求了哪个模型，不能证明第三方服务内部真正运行了哪套权重。
- 成功保存手动切换设置后追加 `event_type=model_switch`、权威角色 `event` 的运行事件。历史投影为明确注明“不是用户发言”的 user 材料，不冒充用户原话或 Agent 自述。
- 首次为已有已知来源历史增加标记会改变对应前缀，可能需要重新暖缓存。之后固定历史标记，本次调用信息置于末尾。离线测试不证明真实供应商缓存命中率。

## 手动切换接口

在本地应用同源页面或自己的同源客户端中：

```javascript
await fetch('/api/local/model', {
  method: 'PUT',
  headers: {'Content-Type': 'application/json'},
  body: JSON.stringify({model: 'your-model-id'})
}).then(r => r.json());
```

`GET /api/local/model` 返回当前模型 ID 与用于材料的简短型号。PUT 沿用本地 `.env` 已配置的 endpoint 和 key，只接受模型 ID，不接收或返回密钥。支持哪种 ID 取决于该 endpoint；保存设置不发付费探测，返回 `connectivity_verified: false`，不代表连通性已验证。重复保存同一 ID 不生成重复事件，配置失败不生成事件。

切换仅作用于主聊天。内部结构化任务、哨兵、漫想及日结仍使用 `.env` 的 `MIRROW_MODEL`。聊天整轮（含工具续轮）冻结模型；并发后台调用用自己的模型，因此历史按各次真实请求结果保存来源。公开宿主只有一个 endpoint/key，不包含私人生产版的跨站线路、自动回退或路由设置页面。切换不会自动重发未完成的消息。

## 日记、认知与 Memory V2

日记、三域认知、Memory V2 分批编码与日终延续均收到独立的型号来源及切换事实材料。规则放在各自任务合同中：不同型号仍是同一 Agent；结合原话、用户反馈与自述区分当时表达和长期认识；型号不证明情绪或人格变化原因，不预设型号性格，不因来源否定真实经历。

认知材料的 `text`、原话 ID、Memory V2 的正文与引用偏移不变。编码 sidecar 绑定当前批真实消息 ID 和 `s1/s2` 引用，不把运行事件伪装成可逐字引用的聊天。切换事件是运行背景，已完成旧批次不回溯重算。

新关闭日期的来源 digest 包含非空型号。旧日期缺失型号时保持原 digest；不为已结算旧日自动回填来源。编码调用前后及提交前核验冻结日期，日结各阶段之后再次核验。V2 的原有批次 manifest 不改为型号数据库；公开宿主依靠不可变消息型号和日级来源冻结保护这些附属信息。

## 验证

```bash
python -m pytest local_app memory-cognition/tests -q
```

专项 `local_app/test_model_provenance.py` 使用临时数据库和合成 transport，验证同模型历史稳定、切换不改旧来源、后台独立型号、整轮冻结、旧日期 digest 兼容、日记/三域认知/Memory V2 输入来源及任务合同。没有调用真实付费模型，不宣称模型质量或缓存收益已验证。生产部署需单独安排；提交本公开仓库不会自动更新任何私人服务器。
