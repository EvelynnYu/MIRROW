# 记忆接口协议

MIRROW 的记忆库(私有模块)不随本仓库开源,但所有消费记忆的路径都走**注入函数**,协议如下。接上你自己的存储(向量库/SQLite/纯文件)即可获得完整功能;不注入则相关功能优雅降级。

## 漫想:get_memories_func

`init_wander_manager(get_memories_func=...)` 注入,漫想的"翻记忆"事件(MemoryFetch)调用它取材。

### 签名

```python
async def get_memories_func(
    min_importance: float = 0.3,   # 最低重要性阈值(0.0-1.0)
    query: str = None,             # 语义搜索查询词;为 None 时随机抽取
    top_k: int = 5,                # 返回条数上限
) -> list[dict]:
    ...
```

### 返回结构

每条记忆是一个 dict:

```python
{
    "id": "abc123",                     # 记忆唯一 ID
    "topic": "上周的旅行计划",            # 主题/标题
    "timestamp": "2026-07-01T20:30:00", # ISO 8601 时间戳
    "importance_score": 0.7,            # 重要性(0.0-1.0)
    "event": "用户提到想去海边……",        # 记忆正文(自然语言)
}
```

### 实现建议

- `query` 非空时做语义/关键词搜索;为空时**随机抽取**(漫想的本意是"无意间想起",不是精准检索)
- 建议排除:用户画像、系统状态快照、待办事项、已休眠/归档的旧记忆——漫想翻到这些会生成很怪的推送
- 返回空列表完全合法:事件会记录"没有找到符合条件的记忆"并正常结束,不推送

### 最小实现示例(SQLite)

```python
import aiosqlite, random

async def get_memories_func(min_importance=0.3, query=None, top_k=5):
    async with aiosqlite.connect("data/memories.db") as db:
        if query:
            cur = await db.execute(
                "SELECT id, topic, ts, score, body FROM memories "
                "WHERE score >= ? AND body LIKE ? ORDER BY score DESC LIMIT ?",
                (min_importance, f"%{query}%", top_k))
        else:
            cur = await db.execute(
                "SELECT id, topic, ts, score, body FROM memories WHERE score >= ?",
                (min_importance,))
        rows = await cur.fetchall()
    if not query:
        rows = random.sample(rows, min(top_k, len(rows)))
    return [{"id": r[0], "topic": r[1], "timestamp": r[2],
             "importance_score": r[3], "event": r[4]} for r in rows]
```

## MemoryProvider:上下文记忆检索协议(批次2)

`memory_provider.py` 定义了 ContextBuilder 使用的标准记忆检索接口。实现这个协议,你的记忆存储(向量库/SQLite/任意后端)就能直接接入上下文组装管道。

### 协议定义

```python
from memory_provider import MemoryItem, MemoryProvider, TodoItem

class MemoryProvider(Protocol):
    async def search(self, text: str, top_k: int = 5,
                    query: str = None,
                    exclude_tags: list[str] = None) -> list[MemoryItem]: ...
    async def list_todos(self, max_results: int = 10,
                        include_dormant: bool = False) -> list[TodoItem]: ...
    async def touch_todo(self, todo_id: str) -> bool: ...
```

- `search` —— 语义/关键词搜索长期记忆。`text` 是当前用户消息(提取检索词),`query` 为显式查询(漫想等场景使用),返回按相关性排序的记忆列表,无结果时返回空列表
- `list_todos` —— 列出活跃待办事项,按紧急度和时间排序,不注入时待办段为空
- `touch_todo` —— 标记待办仍被讨论(重设衰减时钟),失败返回 False 不中断流程

三个方法全部可选实现——未实现的方法被 Builder 静默跳过。

### MemoryItem 数据结构

```python
@dataclass
class MemoryItem:
    id: str                       # 记忆唯一 ID
    content: str                  # 记忆正文(自然语言)
    topic: str = ""               # 主题
    timestamp: str = ""           # ISO 8601 创建时间
    importance_score: float = 0.5 # 重要性(0.0-1.0)
    valence: float = None         # 情感效价(-1~+1)
    arousal: float = None         # 情感唤醒度(0~1)
    domain: str = ""              # 领域
    tags: list[str] = []          # 标签

    @property
    def metadata(self) -> dict:   # OB_Rev 风格兼容
        ...
```

### ContextBuilder 接入示例

```python
from context_builder import ContextBuilder
from memory_provider import SQLiteMemoryProvider

provider = SQLiteMemoryProvider("data/memories.db")
builder = ContextBuilder()

result = builder.build(
    "FULL_CHAT",
    memory_provider=provider,     # ← 注入
    persona="你是用户的AI伴侣,温柔细心。",
    messages=[...],
)
```

不传 `memory_provider` → 记忆段和待办段静默为空,其他上下文段正常组装。
